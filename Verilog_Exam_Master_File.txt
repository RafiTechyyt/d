DIGITAL ELECTRONICS & LOGIC DESIGN LAB VERILOG EXAM MASTER FILE
=================================

IMPORTANT

This is a broad exam-preparation collection based on the topics
discussed: SOP/POS, multiplexers, demultiplexers, binary/Gray
conversion, flip-flops, and synchronous counters. It also includes
common supporting lab programs.

Each design is written as synthesizable Verilog-2001. Testbenches are
included for the main designs. Save the required module and its
testbench in a .v file (or copy only the required sections into a .v
file).

WSL / IVERILOG COMMANDS

Compile: iverilog -o output design.v Run: vvp output Open waveform (if
the testbench creates a VCD file): gtkwave waveform.vcd

IMPORTANT: Use the exact same output filename in the compile and run
commands. Example: iverilog -o outsop sop.v vvp outsop NOT: vvp outstop

A testbench is a simulation-only module. It normally has no input/output
ports. The design module is instantiated inside it. In a testbench, use
reg for signals driven by the testbench and wire for outputs driven by
the design.

============================================================ 1. BASIC
LOGIC GATES ============================================================

module basic_gates(input a, b, output and_y, or_y, not_a, nand_y, nor_y,
xor_y, xnor_y); assign and_y = a & b; assign or_y = a | b; assign not_a
= ~a; assign nand_y = ~(a & b); assign nor_y = ~(a | b); assign xor_y =
a ^ b; assign xnor_y = ~(a ^ b); endmodule

Testbench: module basic_gates_tb; reg a, b; wire and_y, or_y, not_a,
nand_y, nor_y, xor_y, xnor_y; basic_gates uut(a, b, and_y, or_y, not_a,
nand_y, nor_y, xor_y, xnor_y); initial begin
$dumpfile(“basic_gates.vcd”); $dumpvars(0, basic_gates_tb); a=0; b=0;
#10; a=0; b=1; #10; a=1; b=0; #10; a=1; b=1; #10; $finish; end endmodule

============================================================ 4. HALF
SUBTRACTOR ============================================================

SUBTRACTOR ============================================================

Y=%b”,a,b,c,y); end $finish; end endmodule

NOTE: For another SOP question, simplify the given minterms using a
K-map first, then replace the right-hand side of the assign statement
with the simplified Boolean expression. Do not assume every SOP question
has the same expression.

============================================================ 23. SR
LATCH (GATED, ACTIVE-HIGH)
============================================================

module sr_latch(input s,r, output reg q, output qbar); always @(*) begin
if(s && !r) q=1’b1; else if(!s && r) q=1’b0; else if(!s && !r) q=q; else
q=1’bx; // forbidden condition S=R=1 end assign qbar=~q; endmodule

============================================================ 27. JK
FLIP-FLOP ============================================================

module jk_ff(input clk,j,k, output reg q); always @(posedge clk) begin
case({j,k}) 2’b00: q<=q; 2’b01: q<=1’b0; 2’b10: q<=1’b1; 2’b11: q<=~q;
endcase end endmodule

============================================================ 45.
IMPORTANT VERILOG RULES FOR THE EXAM
============================================================

1.  Use ‘assign’ for continuous/dataflow assignments. Example: assign
    y=(a & b) | c;

2.  Use ’always @()’ for combinational behavioral logic. Outputs
    assigned inside this block must be declared reg in Verilog-2001.
    Example: output reg y; always @() begin if(sel) y=b; else y=a; end

3.  Use ‘always @(posedge clk)’ for positive-edge-triggered sequential
    logic. Use nonblocking assignments (<=) for flip-flops and counters.

4.  Use ‘always @(posedge clk or posedge reset)’ for an asynchronous
    active-high reset.

5.  Use blocking assignments (=) in combinational always blocks. Use
    nonblocking assignments (<=) in clocked sequential always blocks.

6.  In a combinational always block, assign every output in every
    possible branch. Give a default value before a case statement to
    avoid latches.

7.  Verilog operators: AND & OR | NOT ~ XOR ^ XNOR ~^ or ^ Equality ==
    Greater > Less < Ternary condition ? true_value : false_value

8.  Bit widths: reg a; // one bit reg [2:0] a; // three bits 3’b101 //
    3-bit binary value 4’d9 // 4-bit decimal value 8’hA5 // 8-bit
    hexadecimal value

9.  Module instantiation: module_name instance_name(port1, port2,
    output1);

    Safer named-port style: module_name uut(.a(a), .b(b), .y(y));

10. A common testbench structure: reg inputs; wire outputs; design
    uut(…); initial begin $dumpfile(“file.vcd”);
    $dumpvars(0,testbench_name); // apply inputs with delays #10;
    $finish; end

11. If Icarus says ‘Unable to open input file’, check that the filename
    after vvp exactly matches the -o filename from iverilog.

12. If GTKWave says the VCD file is missing, check that:

    -   $dumpfile(“name.vcd”) is present
    -   $dumpvars(0,testbench_name) is present
    -   the simulation ran successfully
    -   you are in the correct directory
